## ADR-003：比赛冠军预测模型 — 三模型并存策略

- **背景**：需要提供 F1 比赛冠军预测功能。考虑三种模型：线性逻辑回归（简单可解释）、非线性神经网络（捕捉复杂关系）、RNN 时序嵌入（利用历史序列模式）。问题不是选哪个，而是是否需要三个都保留。
- **选项**：
  - A：**只保留线性逻辑回归** — 优点：可解释性强（能看到每个特征的权重）、训练快、不易过拟合、`evaluateWinnerPredictions()` 已有完善的评测。缺点：无法捕捉特征间的非线性交互
  - B：**只保留非线性神经网络** — 优点：理论上准确率更高（能捕捉复杂关系）。缺点：黑盒不可解释、在小数据集上容易过拟合、需要调参
  - C：**三模型并存** — 优点：各取所长，用户可选择模型，团队可对比研究。缺点：代码量大、维护成本高
- **决策**：选择 C — 保留三个模型。
- **原因**：三个模型文件已存在且工作正常（`raceWinnerPrediction.ts` / `raceWinnerNonlinearPrediction.ts` / `raceWinnerSequenceModel.ts`）。线性模型的 `evaluateWinnerPredictions()` 已有完善的 Evals 基础设施。非线性模型可作为改进基线。RNN 模型用于实验性功能。保留三个的成本主要是代码体积，但每个模型都是独立文件，删除不会简化架构。项目定位为"数据密集型应用"，多模型对比本身就是一种数据产品价值。
- **代价**：维护三个模型的相同接口需要保持一致。未来如果要加新特征，需在三个模型中都更新。建议长期看评测数据决定是否精简——如果某个模型长期不优于其他模型，可考虑移除。
