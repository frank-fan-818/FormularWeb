# 登录确认状态设计

- 主要任务：让首次登录、已有会话恢复和验证回调的等待过程保持清晰、稳定。
- 原因：SiteAccess 在会话未确认时直接返回普通 member-access 卡片，脱离登录页布局，形成横跨屏幕的空白提示。
- 布局：复用登录页 AuthFrame；桌面保留品牌区与居中内容区，手机沿用单列品牌栏。
- 信息层级：账号入口标识、正在确认登录状态、自动进入说明、轻量进度提示。使用现有字体、间距、颜色和动效变量。
- 反馈：进度仅表达等待，不显示虚构百分比；减少动态效果偏好下静止展示。
- 性能：完整确认界面按需加载，资源到达前提供居中的 F1 品牌提示；共享布局样式保留在异步资源中，遵守首屏性能预算。
- 行为：保留首次访问跳转、游客授权、会话校验、回调 URL、超时和重试流程；身份未确认前不展示会员内容。
- 状态：检查完成后进入已有流程；超时或失败仍进入登录页显示已有错误说明和重试入口。
- 验证：慢 SDK 下会员/游客和验证回调均显示完整页面；检查 1440×900、768×1024、375×812，明暗主题，减少动态效果，控制台及网络错误；验证现有登录、退出和密码恢复流程。
