# 新闻、社交精选与进站数据设计草案

日期：2026-10-21。状态：调研与建议，尚未实施，数据接入契约待审定。

后续来源实测见 [新闻与进站数据来源实测](../research/2026-10-21-news-and-pit-stop-sources.md)：已验证新闻 RSS、Jolpica / OpenF1 样本、F1DB 更早历史，以及 DHL 官网 JSON 和多个历史赛季。以下方案需结合该报告的覆盖与使用限制阅读。

用户已明确：内容页需要新闻，也需要 Reddit / 社交平台精选帖子。

## 现状与结论

- 当前没有新闻路由、新闻采集任务或 DHL 榜单接口。
- `src/types/index.ts` 已有 `FastF1PitStop`、`pitDurationSeconds` 和可选 `strategyAnalysis`，但 `scripts/export-fastf1-race-data.py` 没有生成对应进站分析。因此不能只增加表格就认为已有真实数据。
- 当前比赛解读路由及 FastF1 查询有会员边界。新增游客可看的基础计时应使用独立数据查询，不能顺带开放已有私有分析数据。
- 现有 Jolpica 同源代理、Supabase、定时采集工作流可以复用，不必为首版增加独立常驻后端。
- 后续已完成上游样本 HTTP 实测，找到 DHL 官网使用的匿名 JSON 接口；尚未建设本站端到端集成，DHL 接口也没有已确认的公开版本 / SLA 或再发布许可。

## 方案选择

| 方案 | 收益 | 代价 / 前置条件 |
| --- | --- | --- |
| 混合更新，推荐 | 可接入的新闻源自动更新，社交内容人工精选；每站计时自动同步，DHL 官方数据独立导入 | 需要少量内容维护，新闻来源与 DHL 接入须逐个验证 |
| 全自动聚合 | 维护工作较少 | Reddit / 各社交平台访问权限、来源使用条款及页面变化成为主要依赖 |
| 全人工维护 | 最容易控制内容质量 | 新闻时效、赛事数据维护成本随规模增加 |

首版建议采用混合方案，不以 Reddit API 获批或 DHL 自动采集完成作为整个功能发布的前提。

## 内容页：围场动态

### 产品与布局

- 主任务：快速了解近期 F1 动态，再进入原始报道或讨论。
- 新路由建议 `/news`，主导航名称“围场动态”；首页放最近三条，复用同一数据查询。
- 页内切换“全部 / 新闻 / 社交精选”，按发布时间倒序，支持来源筛选与加载更多。
- 卡片显示简短标题、来源或作者、发布时间、内容类别、原文入口。独立撰写的中文导读与原作者内容明确区分。
- 社交讨论、媒体报道、官方公告使用不同类别；讨论和传闻不能呈现为已确认消息。
- 首版不建设站内评论、点赞、用户发帖或自动搬运评论串。
- 桌面采用便于扫描的信息列表，移动端单列；复用现有设计 token，主操作沿用项目红色。

### 来源与更新

- 新闻源采用显式白名单。RSS 存在只代表技术可订阅，不代表获得二次发布、翻译、摘要或图片使用许可。
- FIA 媒体中心提供 RSS 入口，可作为候选来源；使用范围与具体 feed 仍需接入前核实。
- F1 官网当前 RSS 条款明确限制纯聚合、商业聚合及修改/翻译 feed 内容，不应作为默认中文自动聚合源。
- RaceFans 提供 RSS，但其 FAQ 对内容与图片再使用另有约束，不能因可读到 feed 就直接复制图文。
- Reddit 首版建议由维护者提供精选帖子 URL，配本站撰写的导读与原帖入口；不批量采集正文、评论、点赞数或热度。
- 如需显示帖子本体，单独接入符合平台条款的官方嵌入；嵌入按需加载，失败时保留原帖链接。自动读取 Reddit 数据前需要平台访问批准。
- 其他社交平台同样逐个平台决定链接、官方嵌入或授权 API，不承诺统一免费抓取。
- 允许自动聚合的新闻源建议每 30–60 分钟同步一次。该周期是产品建议，不是精确准点承诺。
- 首版可通过配置清单 / 导入脚本维护精选，不必同时开发完整管理后台。

### 最小数据与发布流程

建议新建 `news_items`，保存：ID、类别、本站展示标题、可空导读、来源、作者、原文 URL、原文发布时间、首次收录时间、更新时间、发布状态，以及来源使用方式（链接 / 官方嵌入 / 获准聚合）。图片默认不采集。

流程：允许的来源 → 规范化 URL / 来源 ID 去重 → 字段与来源校验 → 自动或人工发布 → Supabase → `src/api/news.ts` → `src/hooks/useNews.ts` → 页面。

- 仅发布状态可被网站访问者读取；维护写入由已有可信脚本环境执行，服务角色密钥不进入浏览器。
- 首版按 URL 去重，多个媒体对同一事件的报道保留来源，不急于做语义事件聚类。
- 不渲染抓取到的任意 HTML；外链限定 HTTPS，拒绝脚本 URL，嵌入采用固定平台白名单。
- 来源删除或撤回内容时，支持下架；外部平台嵌入的显示遵循平台状态。
- 翻译 / 摘要自动化作为后续选择；不能仅凭可读取原文就假设可送入模型处理或再次发布。

## 进站用时：先统一口径

| 展示名称 | 含义 | 建议来源 | 注意事项 |
| --- | --- | --- | --- |
| 维修区总用时 | 从维修区入口到出口的时间 | Jolpica；较新赛事可用 OpenF1 `lane_duration` 补充 | 含行驶时间，特殊记录可能包含红旗等待；不等于换胎用时或相对赛道的净损失 |
| 静止换胎用时 | 赛车在维修位静止的时间 | OpenF1 `stop_duration` | 文档注明从 2024 美国站起提供；逐场验证覆盖率，缺失保留 null |
| DHL 官方成绩与积分 | 官方认定的最快进站成绩 / 年度车队积分 | DHL / F1 官方榜单 | 独立保存与引用，不能把其他计时排序冒充官方榜单 |

OpenF1 文档已将 `pit_duration` 标为弃用，预计 2026 年底移除。新实现使用 `lane_duration`，保留来源的原始精度，不用补零制造更高精度。

### 页面位置与交互

- 比赛详情的“正赛结果”内增加独立“进站记录”区块，基础计时建议游客可看，页面位置不依赖私有 FastF1 数据加载成功。
- 表格列：车手、车队、第几次进站、圈数、维修区总用时、静止换胎用时、来源。可按车手筛选、按用时排序。
- 两个用时分别排序；缺失值显示“暂无数据”，不显示为 0。
- 标注异常记录与可确认的红旗 / 处罚情况，来源不能判断原因时不自动归因。
- 轮胎变化、进站前后节奏及位置变化以后可接入现有会员比赛解读；首版无需扩展全部策略分析。
- 未开赛显示“赛后更新”，同步中、无记录与加载失败分别呈现。部分数据失败只影响该模块。

### 采集与数据边界

- Jolpica 使用现有 `/f1-api/{season}/{round}/pitstops/` 代理并读取完整分页；文档覆盖从 2011 年起，不能默认所有分站都有完整记录。
- OpenF1 由后台任务在赛后获取并存入 Supabase，避免每名访问者直接请求上游；历史数据从 2023 年起免费，实时数据需要付费，因此首版定位赛后更新。
- 通过赛季、赛事日期、赛道和会话类型匹配 OpenF1 session；不能假设 OpenF1 session key 等于 Jolpica round。
- 车手通过该赛季车号与车手 ID 映射；合并使用赛事、车手、圈数及进站顺序校验，匹配歧义保留分离记录。
- 建议 `race_pit_stops` 保存赛事、车手、圈数、进站序号、两个独立可空用时、各用时来源与抓取时间。不重新定义已有 `pitDurationSeconds` 的含义。
- 赛后任务可在比赛结束后多次重试，再按天核对更正；上游失败保留最后成功数据并显示更新时间，不以空列表覆盖有效数据。

## DHL 榜单：单站与赛季分开

- 新路由建议 `/pit-stops?season=2026`，集中提供“单站最快换胎 / 年度车队积分”；比赛详情可链接到对应分站。
- DHL 官网当前页面存在年度 Overall Standings、赛季最快进站与车队平均用时等区块，适合作为官方核对入口。
- 已验证当季、2018、2024、2025 样本及单站切换；接入时从官方页面动态发现 JSON 地址，不写死 CMS ID。单站实测仅有 10 条最快记录，不能作为全场进站数据。
- 正式接入可以采用有依据的导入快照，后续再增加稳定采集器。快照携带赛季、截至分站、来源 URL、抓取时间及审核状态。
- 官方榜单快照与 OpenF1 排序分开；后者可称“换胎用时排名（OpenF1）”，不称“DHL 官方排名”。
- 有历史 DHL 资料说明过积分分配，但不足以替代当季规则验证。首版优先展示官方积分快照，不自行套用比赛积分算法；如以后自行计算，须确认当季计分、同队多次进站、并列和更正规则并测试。
- 官方数据缺失时显示“官方排名待更新”及官方入口，不编造名次或积分；即使计时数据已齐，也不推断官方成绩。

## 实施顺序与验收

1. 先完成进站数据样本验证：一场近期比赛、一场仅有总用时的历史比赛，以及存在异常 / 缺失数据的案例。审定字段契约后补 API、同步脚本和表格。
2. 实现内容页与人工精选导入，再接入 1–2 个使用方式明确的自动新闻源。若来源许可未解决，先交付精选链接与本站导读。
3. 验证并导入 DHL 官方快照，完成赛季积分与单站榜单；可靠获取方式确认后自动化。

每阶段均保持 API 在 `src/api/`、复用逻辑在 `src/hooks/`、共享类型在 `src/types/`、纯转换在 `src/utils/`。

- 数据测试：分页完整性、重复同步、会话匹配、用时解析与单位、缺失值、异常长记录、来源分别归属、内容去重与发布过滤。
- 权限测试：游客只能读取发布内容与获准公开的基础计时，不能读取新闻草稿或现有会员分析。
- UI 状态：加载、未开赛、空数据、部分成功、过期缓存、失败重试；无数据不能伪装成零次进站。
- UI 完成后遵循 `browser-qa-check`，先相关单测，再生产构建；检查新闻、比赛详情及榜单路由，核对控制台 / 失败请求，保存桌面和移动截图。
- 中英文文案、发布时间沿用站内时区偏好；用时是秒数，不参与时区转换。
- 本草案不增加版本号、不提交、不发布，也不声明浏览器 QA 已完成。
