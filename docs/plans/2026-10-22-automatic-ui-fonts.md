# 自动同步中文字体子集

PR 83 新增新闻文案后，严格字体校验发现 14 个中文字符未进入自托管子集。PR 79 曾出现相同问题：源码更新与手工裁剪字体脱节，普通 build 没有检查字体，直到 CI 才报错。

- 保留严格的字体覆盖、WOFF2 完整性、许可证、SHA-256、CSS / manifest 一致性校验。
- 共享源码字形收集器，兼容真实中文和 Unicode 转义；同步器与校验器使用同一输入规则，并分别覆盖账号核心与账号标题子集。
- 在仓库 scripts/ 中保存锁定版本的官方完整中文字体与许可证，仅作构建输入；发布目录仍只交付原有 8 个小字体。
- `fonts:sync` 先检测缺字，无变化直接退出，无需 Python / 网络；需要补字时使用锁定工具按需生成，验证真实 cmap 后同步 WOFF2、CSS Unicode range、manifest。
- 普通 `npm run build` 的 prebuild、CI 字体验证之前、quality:check 统一自动同步，阻止相同文案变更再次漏掉生成步骤。
- 回归新增文字、转义、账号标题、测试文件排除、幂等运行和 CI 执行顺序；验证损坏字体仍失败，并检查构建预算和浏览器账号首屏 / 字体失败回退。
- 修复继续加入尚未发布的 1.2.0 / PR 83，不另增发布版本。
