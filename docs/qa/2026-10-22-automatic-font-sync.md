# PR 83 中文字体自动同步

根因：新增新闻文案引入 14 个未收录的中文字符，已有字体需要手工裁剪，而普通 build 没有执行字形覆盖检查。PR 79 曾因相同原因阻塞。此次保留严格门禁，并自动补齐生成环节。

实现：

- 共享 UI / 账号核心 / 账号标题的字形收集器，同步与验证使用同一套规则，支持中文、`\uXXXX` 和 `\u{XXXX}`，排除测试文件。
- `npm run build` 的 prebuild、CI 字体验证前和 quality:check 都执行 `fonts:sync`。无缺字时不调用 Python、不下载、不修改文件；新增字形才生成。
- 锁定官方 IBM Plex Sans SC 1.1.0 构建源（3,813,972 字节，SHA-256 和 OFL 许可证随文件保存），放在 scripts/，不进入发布目录。避免每次下载约 114 MiB 的完整 npm 字体包。
- fontTools 4.51.0 / Brotli 1.2.0 使用 PyPI wheel 哈希锁定；只在需要时安装至忽略的 .cache。CI 相关任务显式提供 Python 3.13.11。
- 按实际 cmap 校验生成结果，更新扩展 WOFF2、Unicode ranges 与 manifest；保留没有变化的核心、账号标题和 ASCII 文件。已有严格字体、哈希、许可证和 CSS 声明检查保留，并新增核心覆盖检查。
- 最终 8 个发布字体、712 个声明字形。中文扩展字体从 62,144 增至 63,472 字节（+1,328）；其他 7 个字体保持原样。

验证：

- 先重现原字体检查的 14 项缺字；回归测试先失败，再实现修复。
- `fonts:verify`：3 项脚本测试、8 个字体与 712 个字形全部通过。
- `fonts:test:integration`：在隔离目录新增 UI / 账号标题 / 核心文案，真实 npm build 自动生成并验证成功；重复构建字节保持一致；损坏字体仍失败。当前工作区文案未被测试修改。
- 完整覆盖率测试：101 文件 / 586 测试通过；语句 61.38%、分支 57.25%、函数 61.77%、行 61.74%，全部超过配置阈值。
- 严格 ESLint、编码、生产构建、安全扫描通过；工作流 44 测试 / 7 文件通过；Service Worker 7 项通过，资源预算没有放宽。
- 浏览器：桌面 1440×900、平板 768×1024、手机 375×812 共 9 项通过，覆盖新闻筛选与中文显示、账号首帧和字体请求失败回退，无新增页面错误 / 失败请求（故障用例按设计拦截字体）。
- 确认完整构建源没有复制进 dist；页面交付仍是 8 个小子集。截图在 `artifacts/browser-qa/screenshots/news-*`、`release-login-*` 和 `font-fallback-*`。
